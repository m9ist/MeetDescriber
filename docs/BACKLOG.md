## Запись

**B6 — Механизм перезапуска записи**
Поддержка сценария запланированного длительного отсутствия: возможность
приостановить/продолжить запись без создания новой сессии, или авто-возобновление
после паузы (например, при возвращении звука после тишины N минут).

**B7 — Запрет сна компьютера при активной записи**
Не давать Windows уходить в сон/гибернацию пока идёт запись.
Реализация: `ctypes.windll.kernel32.SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`
при старте захвата, сброс при остановке.

**B12 — "Замутить" источник**
Звук захватывается и пишется, но не воспроизводится в наушники пользователя.
Актуально при записи чужого видео/совещания фоном.
Реализация: WASAPI loopback + mute системного устройства вывода или отдельный silent sink.

**B16 — Выбор приложений для захвата системного звука (macOS)**
Сейчас Core Audio Tap (`mac_tap.py` → audiotee) тапает все процессы. Это
значит в запись попадает фоновая музыка из Spotify, нотификации Slack/Discord
и т.п. Хотим тапать только релевантные процессы:
- Автоматически: PID(ы) Chrome (через Native Messaging — получаем `tabs.processId`),
  плюс Meet-related процессы (audio.googleapis.com, etc.).
- Опционально вручную: чекбоксы в настройках "Что писать" (Chrome, Slack, Zoom...).
audiotee уже умеет `--include-processes <pids...>` / `--exclude-processes`.
Нужно прокинуть PIDs из `app/main.py._handle_meet_started` через `AudioCapture.start()`
до `MacTapCapture.start(include_pids=...)`. Бонус: можно не писать в запись
фоновую музыку даже если пользователь её включил.

## Сделано вне исходного бэклога

**Двухмодельный пайплайн транскрипции** ✅
GigaAM v2_rnnt (Sber, default на Windows) рядом с faster-whisper. Переключатель `TRANSCRIPTION_ENGINE`. Исследование: `research/transcribe_compare/`.

**Subprocess-изоляция тяжёлых ML-стадий** ✅
ctranslate2 и PyTorch конфликтуют по `cudnn64_9.dll` → BEX64 crash. Решение — три worker-процесса (diarize / transcribe-whisper / transcribe-gigaam), JSON через stdout, `PROGRESS:` через stderr.

**Окно «Все совещания»** ✅
Список всех сессий с фильтрами, контекстное меню, ручной запуск отдельных этапов. Колонка «Аудио» показывает session_id для физического доступа к папке `data/recordings/session_<id>/`.

**`tools/transcribe_file.py`** ✅
Standalone-CLI для разовой транскрипции одного файла (mp4/mkv/wav/...) без записи в БД. Опционально с диаризацией. См. `docs/TRANSCRIBE_FILE.md`.

**Alert drift mic↔loopback** ✅
В `_flush_chunk` мониторим расхождение mic-stream и loopback. При >5 сек — toast «⚠ Микрофон лагает» (другое приложение держит mic exclusive или USB-throttling).

**Наблюдаемость смерти приложения** ✅
Приложение иногда исчезало в простое, не оставив следов: faulthandler ловит только
fault'ы, WER молчит, парного лога к `=== app start ===` не было, stderr выбрасывался
лончером. Добавлены `atexit`, `finally` в `main()`, ветки `SystemExit`/`KeyboardInterrupt`,
`threading.excepthook` → лог, `SetConsoleCtrlHandler` (logoff/shutdown), heartbeat раз
в 5 минут с состоянием потоков трея и моста, `ForMeetsTray.is_alive()/restart()` для
случая «умер поток pystray, иконка исчезла, процесс жив», ротация `app.log` при старте
и stderr лончера в `app.err.log`. Таблица «как читать лог» — в `CLAUDE.md`.

**Гонка разрушения аудио-стримов** ✅
`stop()` закрывал loopback-стрим, пока поток `lb-reader` стоял внутри blocking `read()` →
access violation, убивающая процесс (дамп 11.06 в `app.log`). Теперь `stop()` трогает
только mic, разрушение сведено в один `finally` после `join` reader'а, а если reader
застрял — стрим намеренно не закрывается. Заодно закрывается `ThreadPoolExecutor`
оценки качества, который создавался на каждую сессию и жил до конца процесса.

**Логирование действий пользователя** ✅
`app.user_actions.log_action(name, **kwargs)` — все клики по tray/меню/диалогам пишутся в `app.log` с префиксом `app.user_action`.

**Issues #20, #21** ✅
Убрана тост-табличка «Плохо слышно» (#20). Полировка `MeetingStartDialog` (#21): автофокус, убран селектор источника, починен copy-paste на русской раскладке.

**Захват системного звука на macOS без BlackHole** ✅
Перешли с BlackHole virtual driver на Core Audio Taps (macOS 14.4+). Бандлим
Swift-CLI `audiotee` (MIT, `vendor/audiotee/`) внутрь MeetDescriber.app, запускаем
subprocess'ом из `app/capture/mac_tap.py`. Пользователь больше не настраивает
Multi-Output Device — macOS показывает один permission-prompt "System Audio
Recording" при первом запуске. Микрофон по-прежнему через sounddevice, микс
при flush. См. также B16 — выбор PIDs для тапа.
